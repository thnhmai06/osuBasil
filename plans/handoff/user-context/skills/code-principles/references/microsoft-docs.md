# Microsoft guidance: where each rule comes from

Microsoft's official documentation is the first external authority for this skill (see "Precedence" in
SKILL.md). This page lists the documents that back the skill's rules, grouped by topic. Each entry says what
the document settles, and where thnhmai06's style goes further or deliberately differs.

Open the document itself (with the Microsoft Learn MCP server when it is connected) instead of quoting it from
memory. Several Framework Design Guidelines pages are reprints of the 2nd edition (2008), and the book has a
3rd edition, so check the date when a rule looks dated.

## Design: Framework Design Guidelines

Index: [Framework Design Guidelines](https://learn.microsoft.com/dotnet/standard/design-guidelines/)

| Topic                         | Document                                                                                                                                                                                                                                                                                                                                                           | What it settles here                                                                                                                                                                                                                                                                                               |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Naming                        | [General naming conventions](https://learn.microsoft.com/dotnet/standard/design-guidelines/general-naming-conventions), [Names of type members](https://learn.microsoft.com/dotnet/standard/design-guidelines/names-of-type-members), [Names of classes, structs and interfaces](https://learn.microsoft.com/dotnet/standard/design-guidelines/names-of-classes-structs-and-interfaces) | Full words, no abbreviations (`Privilege`, not `Priv`), readability over brevity, no Hungarian notation. The skill adds: one name per concept, mechanism-neutral contract names, at most three words per class name.                                                                                                |
| Properties                    | [Property design](https://learn.microsoft.com/dotnet/standard/design-guidelines/property)                                                                                                                                                                                                                                                                          | Getters are cheap and don't throw. A setter keeps the previous value when it throws. No set-only properties. The skill adds: a setter only assigns and validates, and a change with consequences is a method.                                                                                                      |
| Members                       | [Member design](https://learn.microsoft.com/dotnet/standard/design-guidelines/member), [Parameter design](https://learn.microsoft.com/dotnet/standard/design-guidelines/parameter-design)                                                                                                                                                                         | Property or method; the least specialized parameter type.                                                                                                                                                                                                                                                         |
| Types                         | [Type design](https://learn.microsoft.com/dotnet/standard/design-guidelines/type), [Choosing between class and struct](https://learn.microsoft.com/dotnet/standard/design-guidelines/choosing-between-class-and-struct), [Interface design](https://learn.microsoft.com/dotnet/standard/design-guidelines/interface), [Sealing](https://learn.microsoft.com/dotnet/standard/design-guidelines/sealing) | Class or struct; when an interface earns its place. The skill is stricter about interfaces: none with a single implementation, except contracts across a module boundary and ports outside the process. It also seals by default.                                                                                 |
| Events                        | [Event design](https://learn.microsoft.com/dotnet/standard/design-guidelines/event)                                                                                                                                                                                                                                                                                | C# `event` members. The skill's domain events are records published on a channel instead (see design.md), so most of this page applies only to UI and component events.                                                                                                                                           |
| Errors                        | [Exceptions](https://learn.microsoft.com/dotnet/standard/design-guidelines/exceptions), [Exception throwing](https://learn.microsoft.com/dotnet/standard/design-guidelines/exception-throwing), [Using standard exception types](https://learn.microsoft.com/dotnet/standard/design-guidelines/using-standard-exception-types), [Exceptions and performance](https://learn.microsoft.com/dotnet/standard/design-guidelines/exceptions-and-performance) | Exceptions report execution failures; no exceptions for normal control flow; the Tester-Doer and Try patterns. The skill extends the Try pattern to an outcome type when the caller must branch on the reason (`JoinResult`). The guidelines say "don't return error codes"; an outcome that is part of the member's meaning is not a generic error code. |
| Collections                   | [Guidelines for collections](https://learn.microsoft.com/dotnet/standard/design-guidelines/guidelines-for-collections)                                                                                                                                                                                                                                             | No `List<T>` or `Dictionary<TKey, TValue>` in public APIs; `IEnumerable<T>` parameters; never return `null` for a collection; no settable collection properties; snapshot versus live collections.                                                                                                                  |
| Disposal                      | [Dispose pattern](https://learn.microsoft.com/dotnet/standard/design-guidelines/dispose-pattern), [Implement a Dispose method](https://learn.microsoft.com/dotnet/standard/garbage-collection/implementing-dispose), [Implement a DisposeAsync method](https://learn.microsoft.com/dotnet/standard/garbage-collection/implementing-disposeasync)                    | Who disposes what, and how to implement it.                                                                                                                                                                                                                                                                       |

## Code: C# conventions and analyzers

| Topic                  | Document                                                                                                                                                                                                                                                                          | What it settles here                                                                                                                                                                                                                                                                                |
|------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Coding conventions     | [Common C# code conventions](https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/coding-conventions)                                                                                                                                                             | Modern language features, LINQ for collection manipulation, collection expressions, raw string literals, file-scoped namespaces, `using` outside the namespace, catch only what you can handle. It is also the default layout for a repository without an `.editorconfig` (4 spaces, Allman braces). |
| Identifier names       | [C# identifier naming rules and conventions](https://learn.microsoft.com/dotnet/csharp/fundamentals/coding-style/identifier-names)                                                                                                                                               | PascalCase and camelCase, `I` prefix, `_field` for private fields, camelCase primary constructor parameters on classes and PascalCase on records. A repository's `.editorconfig` naming rules override it.                                                                                         |
| Style analyzers        | [Code-style rules (IDExxxx)](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/), [Code-style rule options](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/code-style-rule-options)                                                        | How `.editorconfig` encodes and enforces style. Look a rule up here before claiming it is a tooling requirement.                                                                                                                                                                                     |
| `ConfigureAwait`       | [CA2007: Do not directly await a Task](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca2007)                                                                                                                                                       | `ConfigureAwait(false)` for library code; application code may suppress it. The rule also reports `await using` and `await foreach`, and the skill applies it to every `await` in library projects, those two forms included.                                                                                          |
| XML doc comments       | [Recommended XML tags](https://learn.microsoft.com/dotnet/csharp/language-reference/xmldoc/recommended-tags)                                                                                                                                                                     | Which tags exist and how they render. The skill adds the Implementation Test for their content (docs.md).                                                                                                                                                                                         |
