# Kế hoạch: chuyển storage từ SQLite sang PostgreSQL 18

Trạng thái: **đã duyệt lại 2026-10-08 sau review** (đối chiếu AGENTS.md, docs và code); chưa triển khai code. Đã có
sẵn role `basil` và database `basil` trên PG 18 local. Phạm vi: chỉ `src` (hosts, tests, docs để sau).

## Vì sao chuyển

Để mở rộng quy mô và ghi song song: SQLite chỉ cho **một writer** tại một thời điểm, PostgreSQL cho nhiều transaction
ghi cùng lúc. Kế hoạch này đổi lớp storage để ghi song song (P13), không chỉ thay driver.

**Đánh đổi:** Basil mất tính chất "self-contained storage" mà README và `docs/for-developers/database.md` ("Why
SQLite?") coi là tính năng (không cài DB server, không credentials, chép cả deployment là xong). Từ nay cần một
PostgreSQL server. README, `database.md`, `configuration.md`, Docker sửa ở đợt docs sau.

## Mục tiêu

- Thay SQLite bằng PostgreSQL 18 (`localhost:5432`, service `postgresql-x64-18`). Không giữ song song hai DB.
- **Giữ kiến trúc RAM-first** (AGENTS.md, mục "Memory is the truth; the database is a snapshot of it").
  - Cache (`IdentityMap`, `OwnedLists`, `CachedRepository`, `MatchReportCache`) giữ nguyên.
  - Lưu không chờ DB; lệnh thử (try-operation) chờ DB; đọc thấy cái đã commit.
  - Hợp đồng `IXxxRepository` không đổi; Application không biết DB đổi.
- **Đường đọc/ghi viết lại cho PG** (mục "Thiết kế"): `DatabaseBatcher`, `DatabaseWorker`, `DatabaseOperation`,
  `DatabaseBatch`, `ReadOperation`, `SqliteErrors` sinh ra vì SQLite một writer nên bị bỏ.
- Thay đổi nằm trong `Basil.Infrastructure.Storage` và AGENTS.md, **trừ** P14: Domain chặn `\0` và hai service đổi
  lỗi đó thành kết quả.

## So sánh

| Phần | SQLite hiện tại | PostgreSQL |
|---|---|---|
| Driver | `Microsoft.Data.Sqlite` | `Npgsql` 10.0.3 (MIT, driver chính thức), giữ `Dapper` cho đọc và lệnh thử |
| Kết nối | mở file mỗi lần | `NpgsqlDataSource` singleton (pool có sẵn) |
| Đọc | xếp qua worker, WAL | mở thẳng từ pool, MVCC `READ COMMITTED`: chỉ thấy cái đã commit |
| Ghi | 1 hàng chờ, 1 worker, savepoint mỗi lệnh, mỗi lệnh 1 lượt mạng | `WriteLanes` làn song song; bản chụp liền nhau gửi bằng 1 `NpgsqlBatch`; savepoint chỉ cho lệnh thử |
| Tên | `PascalCase` | `snake_case`; Dapper `DefaultTypeMap.MatchNamesWithUnderscores = true` |
| Thời gian | `INTEGER` Unix ms | `timestamptz` (UTC) |
| Boolean / IP / JSON | `INTEGER` / `TEXT` / `TEXT` | `boolean` / `inet` / `jsonb` |
| Số thực | `REAL` (8 byte) | `double precision` (PG `real` chỉ 4 byte) |
| Id tự tăng | `AUTOINCREMENT` (cho ghi id tường minh) | `integer GENERATED BY DEFAULT AS IDENTITY` (`bigint` cho `logins`, `match_events`); upsert bản chụp ghi `id` nên **không** dùng `ALWAYS` (lỗi `428C9`) |
| Id local beatmap/set (≥ 1e9) | `MAX(Id)+1` | `SEQUENCE local_beatmap_ids` / `local_beatmapset_ids` bắt đầu từ 1 000 000 000 (= `LocalIdFloor` của Domain) |
| Danh sách tham số | Dapper bung `IN @x` | Dapper gửi mảng gốc với Npgsql: viết `= ANY(@x)` / `<> ALL(@x)` |
| So khớp chuỗi | `LIKE` không phân biệt hoa thường (ASCII) | `ILIKE` |
| JSON | `json_extract(b.Objects,'$.Circles')` | `(b.objects->>'Circles')::int` |
| Ký tự `\0` | lưu được | `text` từ chối (`22021`) ⇒ Domain chặn (P14) |
| Lỗi trùng | `SqliteException` mã 19 | `PostgresException.SqlState == PostgresErrorCodes.UniqueViolation` (`23505`) |
| Migration | `PRAGMA user_version` | bảng `schema_version`, mọi migration chờ áp dụng chạy trong **một transaction** |

## Chính sách

**P1. Batch ghi.** Mỗi làn có batch đến hạn khi đủ **100 lệnh ghi**, khi lệnh cũ nhất đã chờ **50 ms**, hoặc
**ngay khi có một lệnh thử** (đăng nhập, đăng ký, nộp điểm không chờ thêm 50 ms). Lệnh ghi mới cho cùng identity thay
lệnh cũ tại chỗ. Các `WriteCommand` liền nhau trong batch đi bằng một `NpgsqlBatch` (một lượt mạng).

**P2. Kiểu dữ liệu.**
- Id `integer GENERATED BY DEFAULT AS IDENTITY` (domain dùng `int`); `bigint` cho `logins`, `match_events`.
- `permissions`, các mặt nạ quyền và tổng điểm dùng `bigint`; enum và các đếm dùng `integer`.
- `star`, `bpm`, `cs`, `ar`, `od`, `hp` dùng `double precision`.
- MD5 lưu `text` hex chữ thường; `objects` của beatmap lưu `jsonb`; IP lưu `inet`; thời gian lưu `timestamptz`.

**P3. Ràng buộc DB là lớp bảo vệ cuối cùng.**
- Luật nghiệp vụ nằm ở ứng dụng; toàn vẹn dữ liệu nằm ở DB. Hai lớp tách biệt.
- Giữ `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE` (`users.safe_name`, `beatmaps.hash`, `scores.checksum`), `NOT NULL`,
  và các `CHECK` thuần toàn vẹn (`settings.id = 1`, id ≥ 1).
- Không đặt `CHECK` mang tính luật nghiệp vụ (ví dụ `ends_at ≥ starts_at`): luật đó do ứng dụng giữ.
- Cột suy diễn do DB giữ: `safe_name GENERATED ALWAYS AS (replace(lower(name), ' ', '_')) STORED` (tên chỉ gồm
  ASCII nên khớp `SafeName` trong C#), id, sequence.

**P4. Lỗi ghi.** Phân loại **theo đúng thứ tự**:
1. **Lỗi môi trường** (`NpgsqlException.IsTransient`: mất kết nối, timeout, `40001`, `40P01`, `53300`, `57P01`…) xảy
   ra trước `COMMIT`: PG đã rollback. Chạy lại **cùng batch**, độ trễ 50 ms nhân đôi mỗi lần, tối đa 5 s, không giới
   hạn số lần. Lệnh ghi đến sau của làn đó chờ; các làn khác vẫn chạy. Kiểm cái này trước, vì đứt kết nối giữa
   `NpgsqlBatch` cũng có thể gắn `BatchCommand`.
2. **Đứt kết nối lúc `COMMIT`** (không biết đã commit chưa): mở kết nối mới, hỏi `pg_xact_status(xid)`:
   - `committed`: coi như xong;
   - `in progress`: chờ rồi hỏi lại;
   - `aborted`, `null`, hoặc lỗi "transaction ID … is in the future" (sau khi PG phục hồi từ crash): coi là aborted,
     chạy lại.
3. **Lỗi lập trình** (sai cú pháp, vi phạm ràng buộc):
   - lệnh thử: lỗi trả về nơi gọi (sau commit, P5); lỗi trùng là kết quả bình thường (`false`, `null`);
   - `WriteCommand`: `NpgsqlException.BatchCommand` chỉ ra câu hỏng; log Critical, bỏ câu đó, chạy lại phần còn lại
     của batch ngay.

Chạy lại không ghi đè dữ liệu mới hơn: cùng identity luôn cùng làn và chạy tuần tự, batch đang thử lại luôn chạy trước
mọi lệnh đến sau của làn.

**P5. Savepoint và thời điểm trả kết quả.**
- `WriteCommand` chạy không savepoint: một câu hỏng làm transaction hủy, rồi xử lý theo P4.3.
- Lệnh thử chạy trong savepoint riêng: lỗi của nó được rollback về savepoint và **ghi lại**, batch vẫn chạy tiếp.
- **Chỉ trả kết quả cho nơi gọi sau khi `COMMIT` thành công.** Kết quả của từng lệnh thử được ghi theo từng lần chạy
  và xóa khi batch chạy lại; nếu không, nơi gọi có thể nhận id hoặc "tên đã dùng" của một transaction chưa từng commit.

**P6. Độ bền khi commit.**
- Batch chỉ có bản chụp và append: `SET LOCAL synchronous_commit = off`. Commit không chờ WAL xuống đĩa. Nếu máy sập
  có thể mất các transaction vừa báo commit, tối đa khoảng 3 × `wal_writer_delay` (mặc định 200 ms ⇒ ~600 ms). Mất dữ
  liệu cuối, không hỏng dữ liệu (đúng tinh thần RAM-first: lệnh còn trong hàng chờ cũng mất khi sập).
- Batch có lệnh thử: giữ `on`.

**P7. Pool kết nối.**
- Một `NpgsqlDataSource`.
- Đồng thời thực tế: `WriteLanes` kết nối ghi, cộng tối đa `ProcessorCount × 2` lệnh đọc (giới hạn bằng
  `SemaphoreSlim` để một đợt đọc dồn không chiếm hết pool). Xa dưới giới hạn pool của Npgsql (100) và
  `max_connections` của PG (mặc định 100, giới hạn cho cả server). Không cần PgBouncer.

**P8. Index** (chỉ cái truy vấn dùng thật).
- `users_safe_name` (unique).
- `restrictions (user_id)`, `logins (user_id, timestamp desc)`, `beatmaps (hash)` unique, `beatmaps (beatmapset_id)`,
  `beatmaps (mode)`, `matches (ended_at)`, `match_events (match_id)`.
- `scores (checksum)` unique, `scores (user_id)`, `scores (beatmap_hash)`, `scores (match_id, round_number)` (partial,
  `where match_id is not null`).
- `users_safe_name_trgm` (GIN `gin_trgm_ops`, extension `pg_trgm`) cho tìm user theo một phần tên: **chỉ giữ nếu
  benchmark (P13) cho thấy lợi**.

**P9. Bảng cập nhật thường xuyên.** `fillfactor = 90` cho `users`, `user_stats`, `matches`, `rounds` để **tăng khả
năng** PG cập nhật tại chỗ (HOT); cập nhật đổi cột có index thì không HOT. **Chỉ giữ nếu benchmark đo thấy tỉ lệ HOT
tăng.** Autovacuum giữ mặc định; chỉnh khi đo.

**P10. Migration.**
- `001_baseline.sql` viết lại cho PG. Chưa có dữ liệu thật, nên không chuyển dữ liệu từ SQLite.
- Migrator giữ cách "SQL nhúng + bảng version"; mọi migration chờ áp dụng và việc ghi version chạy trong **một
  transaction** (DDL của PG có transaction). Không dùng advisory lock: một database chỉ cho một tiến trình Basil (P13).
- Bỏ `DataPaths.Database` (file `Basil.db`).

**P11. Cấu hình.**
- `StorageOptions.ConnectionString` (bắt buộc) và `StorageOptions.WriteLanes` (mặc định tạm `4`, thay bằng số đo của
  P13).
- Khi migrate host: `Basil.Host` bind `Basil:Database:ConnectionString` từ `Data/appsettings.json` (file mẫu để
  placeholder mật khẩu như `Server:CertPassword`; mật khẩu dev trong `Data/appsettings.Development.json`, thêm vào
  `.gitignore`). Host không đọc biến môi trường hay user-secrets.
- App chạy bằng role `basil` (không phải superuser).

**P12. Kiểm chứng trong lúc làm.** Không có smoke giao cho agent; Claude chạy script trong scratchpad với PG local (mục
"Kiểm chứng").

**P13. Ghi song song theo làn.**
- `DatabaseWriter` có `WriteLanes` làn. Mỗi làn có hàng chờ riêng, ngưỡng batch P1 và vòng lặp riêng. Tối đa một batch
  mỗi làn đang chạy, nên mỗi làn giữ đúng thứ tự.
- Chọn làn theo **gốc** (root) của dữ liệu: `lane = (uint)root.GetHashCode() % WriteLanes`.
  - `Roots.User(id)`: user, credentials, restrictions, relationships (theo actor), logins, user stats, điểm không thuộc
    trận.
  - `Roots.Match(id)`: match, rounds, match events, điểm trong trận.
  - `Roots.Beatmapset(id)`: beatmapset, beatmaps.
  - `Roots.Server`: settings, channels, menu banners.
  - `Roots.*` là record struct so sánh theo giá trị; không bao giờ dùng `new object()` làm gốc.
- Bất biến:
  - gốc của một identity không bao giờ đổi;
  - con chỉ tham chiếu cha **khác gốc** khi cha đã commit (cha tạo bằng lệnh thử đã chờ); cha cùng gốc nằm cùng làn
    nên đúng thứ tự. Vì vậy FK (P3) an toàn với nhiều làn, và một lỗi FK là bug thật (P4.3), không xếp lại hàng;
  - một database chỉ cho một tiến trình Basil (ghi nhận, không cưỡng chế).
- Tranh chấp giữa các làn chỉ ở unique key và khóa FK của cha (`FOR KEY SHARE` không chặn update thường); deadlock
  `40P01` là lỗi môi trường (P4.1).
- `WriteLanes` chọn theo **số đo, có chứng cứ** ở `plans/evidence/postgresql-write-lanes-<ngày>/` (cách đo ở mục
  "Kiểm chứng").

**P14. Chuỗi có `\0`.** PG `text` không nhận `\0`. Domain chặn: một helper trong `Basil.Domain.Utilities`, các setter
chuỗi được lưu ném `ArgumentException` khi có `\0` (tên trận, trường client của login, metadata beatmap, topic kênh,
`Detail` của match event…).
- `AuthService` đã đổi `ArgumentException` thành kết quả.
- `RoomSettingsService` (đặt tên trận) và `LobbyService` (tạo trận) chưa làm việc này; tên rỗng hiện đã lọt ra ngoài
  thành exception. Hai chỗ này đổi lỗi thành `RoomResult`.
- Đăng nhập có `\0` trong trường client: từ chối, đi nhánh đăng nhập thất bại có sẵn (chỉ client sửa đổi mới gửi
  `\0`).

## Thiết kế

Thư mục `Batching/` đổi thành `Writing/`. Mọi type đều `internal`.

| Type | Vai trò |
|---|---|
| `Database` | Bọc `NpgsqlDataSource.Create(options.ConnectionString)`. `ReadAsync<T>(Func<NpgsqlConnection, Task<T>>, ct)` mở thẳng kết nối từ pool, giới hạn `ProcessorCount × 2`. `IAsyncDisposable`. |
| `DatabaseWriter` (`BackgroundService, IHostedLifecycleService`) | Giữ các `WriteLane`, chọn làn theo gốc. `StoppedAsync` ghi nốt mọi làn song song, dừng theo token; còn lệnh chưa ghi thì log Critical kèm số lượng. |
| `WriteLane` | Hàng chờ `OrderedDictionary<object, …>` (lệnh mới cùng identity thay lệnh cũ), luật đến hạn P1, vòng lặp, chạy batch trong transaction của chính nó, thử lại theo P4. |
| `WriteCommand(string Sql, object Parameters)` | Một câu SQL ghi ở dạng dữ liệu. Mọi bản chụp, append, xóa đều là một câu (`RetainAsync`: `delete … where beatmapset_id = @SetId and id <> all(@KeepIds)`; mảng rỗng thì xóa hết). Tham số lấy từ thuộc tính của object (bộ đọc có cache theo type). |
| `Roots` | `User(int)`, `Match(int)`, `Beatmapset(int)`, `Server`. |

API cho repository (trên `DatabaseWriter`):
- `EnqueueAsync(root, identity, WriteCommand)`: bản chụp, gộp theo identity.
- `AppendAsync(root, WriteCommand)`: dòng lịch sử.
- `WriteAsync<T>(root, Func<NpgsqlConnection, NpgsqlTransaction, Task<T>>, ct)`: lệnh thử, cần kết quả.

Một batch của một làn:
1. `BEGIN`.
2. Một lượt mạng mở đầu: `SET LOCAL synchronous_commit = off` (khi không có lệnh thử) và `SELECT pg_current_xact_id()`.
3. Chạy theo thứ tự hàng chờ: các `WriteCommand` liền nhau gửi bằng một `NpgsqlBatch`; mỗi lệnh thử chạy trong
   `SAVEPOINT` riêng (P5).
4. `COMMIT`, rồi mới trả kết quả cho từng lệnh.

Repository:
- `CachedRepository(Database, DatabaseWriter)` thêm `protected abstract object RootOf(T item)`.
- `SaveAsync` gửi `new WriteCommand(WriteSql, WriteParameters(live))`; `EraseAsync` thành `EraseCommand(key)`.
- Mọi SQL sang `snake_case`; tham số thời gian là `DateTimeOffset` UTC; boolean thật; `@objects::jsonb`;
  `IPAddress` cho `inet`; id local lấy bằng `nextval(...)`; bắt trùng bằng `PostgresErrorCodes.UniqueViolation`.
- `Sqlite*Repository` đổi tên thành `Postgres*Repository` bằng `git mv`, namespace giữ nguyên.
- `BeatmapQueryFilter`, `SqliteMatchRepository.BuildFilter`, `MatchReportRepository` cũng đổi theo bảng so sánh.

Bản nháp cũ ở scratchpad `pg-draft.patch` chỉ để tham khảo schema. Đừng chép nguyên: nó còn `GENERATED ALWAYS`,
advisory lock và Batcher/Worker kiểu cũ.
